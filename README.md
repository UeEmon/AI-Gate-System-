# AI Gate System

OpenCV・YOLO・EasyOCRによる車両区分・日本のナンバープレート読取候補を、Web画面で管理する初期試作版です。

## 入力方式

| 方式 | 入力 | 動作 |
|---|---|---|
| リアルタイム | 操作端末のWebカメラ、処理PCのUSBカメラ、RTSPカメラ | 最新フレームを優先して連続認識。Web画面から停止 |
| ノンリアルタイム | 画像・録画動画のアップロード | ファイルを指定間隔で順番に処理し、終了時に完了を表示 |

操作端末のWebカメラは、ブラウザのカメラ許可を得てJPEGフレームをHTTPS（またはlocalhost）でサーバーへ送信します。
処理PCのUSB/RTSPカメラは従来どおりサーバー側で取得します。
処理は同時に1件、ファイルは1回につき1ファイルです。自動キューと複数カメラ同時処理は未実装です。

## 起動（Windows PowerShell / Python 3.11推奨）

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe web.py
```

ブラウザで **http://127.0.0.1:8080** を開きます。
macOS/Linuxでは `python3 -m venv .venv` を実行し、Pythonのパスを `.venv/bin/python` に置き換えてください。
必要なOpenCVのOS共有ライブラリは環境に応じて導入してください。

1. 「カメラ」または「ファイル」を選択します。
2. 「端末Webカメラ」を選ぶか、カメラ番号（通常 `0`）、RTSP URL、画像・動画ファイルを指定します。
3. 「認識を開始」を押します。
4. 処理モニターに検出枠付き画像、処理フレーム数、検出レコード数が表示されます。
5. 認識履歴で車両区分・ナンバー候補・信頼度・切り抜き画像を確認します。
6. カメラは「停止」で終了。ファイルは読込終了時に完了します。処理履歴の「表示」で過去の処理を選択できます。

WebサーバーはWaitress、認識処理は別のPythonプロセスで動作します。
モデル初回取得中も画面から停止できます。停止時は終了を要求し、30秒以内に終了しない処理を強制終了します。
保存済みの観測結果は残ります。停止時点の処理途中のフレームは保存されない場合があります。

## 車両登録・通知・映像保存

### CSV管理

「登録リストをCSV出力」で全登録車両（無効を含む）をUTF-8 BOM付きCSVとして取得します。
列順は `region,category,kana,serial,vehicle_type,label,watch,enabled` です。サンプルは `examples/vehicles.csv`。
取り込みはUTF-8またはCP932、最大5MB・10000件です。車種は `car/kei/motorcycle/bus/truck`、フラグは `0/1` または `true/false`。
「内容を検証」で保存前の件数を確認し、「検証したCSVを取り込む」で確定します。
既定は登録済みをスキップ。更新モードは同じナンバーの車種・登録名・通知指定・有効状態を更新します。
CSV内の重複や不正な行があると全体を拒否し、行番号を表示します。CSVにない登録は削除しません。
表計算ソフトの数式実行を防ぐため危険な先頭文字を持つセルはアポストロフィで保護し、この取込機能では復元します。
Excelで編集する際は番号列を文字列として読み込んでください。検証後に別の管理者が変更すると、確定時の件数が変わる場合があります。

### カメラ読み取りによる初期登録

連続登録では、認識を開始した後「連続取り込みを開始」を押します。表示中の処理に固定して、
既存履歴と新しい結果を約1.5秒ごとに順番に読み出します。候補の画像・番号を確認してチェックを付け、
「選択した車両を一括登録」で保存します。取り込み停止はカメラの認識を停止しません。

- 同じナンバーは1件に集約。登録済み（無効化済みを含む）はスキップし、上書きしません。
- OCR信頼度0.6以上で通常形式の番号を解析できた候補を取り込みます。未読取・低信頼度は個別の認識履歴から確認します。
- 同じナンバーで車種が変わった候補は一括登録不可。「個別確認・修正」から確認して保存します。
- 最大100件で取り込みを一時停止。登録後に再開すると、続きの認識結果から取得します。
- 一括登録の登録名は空欄、通知指定はオフ、有効状態はオンです。変更は個別確認か登録後の編集で行います。
- 不正な項目がある場合、その一括登録を全件取り消します。重複のみスキップして他の車両を保存します。
- 候補一覧はブラウザ内に保持します。再読み込み・候補クリア後は履歴から再取得でき、登録済みは除外します。

1. 「カメラ入力へ」から入力設定へ移動し、「端末Webカメラ」またはUSB/RTSPカメラで認識を開始します。
2. 対象車両のナンバーを撮影し、認識履歴の「登録に取り込む」を押します。複数車両がある場合は対象の行を選びます。
3. 登録フォームに読み取り画像・ナンバー候補・車種区分・信頼度を表示します。候補が複数あれば選択し、誤読や不足項目を修正します。
4. 登録名や通知指定を入力し、「登録・更新」でデータベースへ保存します。

取り込み時点では保存せず、確認中のフォームは新しいフレームで上書きしません。
読取不可の番号は空欄になるため、再撮影または手入力が必要です。
同じ番号の重複登録は拒否し、既存データは登録車両一覧の「編集」から変更します。
画像・動画ファイルの認識履歴からも同じ手順で登録できます。
認識処理中の通知・照合は引き続き動作するため、初回登録前には未登録通知が発生する場合があります。
保存後の認識から登録内容を照合に使用します。過去の通知は変更しません。

Web画面の「登録車両」で、地名・分類番号・ひらがな・一連指定番号と車種区分を登録します。
ひらがなはナンバープレートで使用される通常文字1文字に限定し、小書き・濁音・半濁音と
`お・し・へ・ん` は受け付けません。一連指定番号は区切り記号を含まない半角数字1〜4桁です。
OCR原文に含まれる全角数字・中点・ハイフンは候補解析時だけ正規化し、修正・登録・CSV・学習の
正解値には半角数字だけを使用します。
ナンバーと車種を組み合わせて照合し、以下を通知一覧に表示します。

| 検知結果 | 通知・証拠保存 |
|---|---|
| 未登録のナンバー | 通知し、検知前3秒・後5秒の映像を保存 |
| 登録ナンバーだが車種区分が不一致 | 通知・映像保存 |
| 登録車両で「通知対象」に指定 | 一致した際に通知・映像保存 |
| 通常の登録車両と一致 | 認識履歴のみ保存 |
| ナンバーを読み取れない／信頼度が不足 | 「ナンバー要確認」として通知・映像保存 |

同一処理内の同じナンバー・車種・通知理由は、入力時刻で60秒間隔にまとめます。
同じ番号を持つ別車両の識別や通過イベント単位の追跡は行いません。
登録内容の編集・無効化、通知の確認済み操作、保存映像の閲覧が可能です。
映像は最大幅960px・5FPS・音声なしです。FFmpegがあればMP4、なければAVIで保存します。
入力開始直後・終了・停止や推論の遅延では前後の映像が短くなる場合があります。
静止画像入力では検知画像を保存します。詳細な制限は [AWS構成・運用仕様](deploy/AWS.md) を参照してください。

メール通知にはAmazon SESを使用します。Webサーバーの環境変数に `AWS_REGION`、
`GATE_EMAIL_FROM`、`GATE_EMAIL_TO`（複数宛先はカンマ区切り）を設定し、AWS認証情報とSESの送信許可を用意します。
メール本文には検知内容と `GATE_PUBLIC_URL` の管理画面リンクを含め、映像は添付しません。
送信失敗時は最大5回まで再試行し、失敗後は画面から再送できます。「SES受付済み」は受信箱への到達を保証しません。
設定がない場合も画面通知・ローカル映像保存は動作します。
通知・メール送信は `python web.py` で起動する管理サーバーで動作します。
CLIの `--alerts` は照合・映像保存・通知キュー作成までで、メール/S3の配送ワーカーは起動しません。

## AWSでの実行

EC2上でDocker Composeを使用し、EBSに登録・通知データと映像を保存する構成を追加しています。
CaddyによるHTTPS、SESによるメール、任意のS3アーカイブに対応します。
SQLiteを使用するため、単一サーバー・単一管理プロセス構成です。
現地のRTSPカメラにはVPN等のネットワーク経由で接続します。AWSから現地USBカメラに直接接続はできません。

[構築手順・環境変数・IAM設定・保存仕様](deploy/AWS.md) に従って設定してください。
Dockerイメージのビルド、AWSへの配備と実メール送信は未検証です。

## 他のPC・タブレットから管理する

環境変数 `GATE_ADMIN_PASSWORD` に管理パスワードを設定し、次のように起動します。

```powershell
# 下記の値を運用用のパスワードに置き換えてください
$env:GATE_ADMIN_PASSWORD = "replace-with-your-admin-password"
.\.venv\Scripts\python.exe web.py --host 0.0.0.0 --port 8080
```

同じLANのブラウザで `http://処理PCのIPアドレス:8080` を開きます。
ユーザー名は `admin`、パスワードは設定した値です。アクセス元に応じてOSのファイアウォールを設定してください。
既定はローカル接続のみ。LAN公開はパスワードが未設定だと起動しません。
HTTPのBasic認証自体は通信を暗号化しないため、LAN以外への公開や信頼できないネットワークでの利用にはHTTPSリバースプロキシ等が必要です。
多人数向けのアカウント管理・権限分離・監査証跡は未実装です。

**同じ保存先に対して起動するWebサーバーは1プロセスに限定してください。**
サーバー再起動時には未完了ジョブを「中断」にします。自動再開はしません。

## オプション

```bash
python web.py --port 8080 --data data --model yolo11n.pt
# 従来のコマンドラインも利用可能
python app.py --source car.jpg --source-kind file --save-images
python app.py --source gate.mp4 --source-kind file --every 1
python app.py --source 0 --source-kind camera --every 1
```

- 画像：JPEG / PNG / BMP / WebP / TIFF。
- 動画：MP4 / AVI / MOV / MKV / M4V / WebM。実際の読込可否はOpenCVのコーデックに依存します。
- アップロード：512MB以下。サーバー側で生成したファイル名で保存します。
- 処理間隔：`1` は毎フレーム。ファイルはその順番を保ち、カメラでは処理待ちの古いフレームを捨てます。
- プレビュー：約1.5秒間隔で取得する処理済みJPEGです。入力カメラと同じFPSを保証するものではありません。
- カメラ切断時は処理失敗になります。自動再接続はありません。
- CPUで認識します。YOLO・EasyOCRの重みは初回にインターネットから取得します。

## 保存データ

`data/gate.db` の `observations` に認識結果、`jobs` に処理履歴を追記します。
`vehicles` に登録車両、`alerts` に通知・映像・メール/S3配送状態を保持します。
既存の観測テーブルはそのまま利用し、WALモードで画面からの参照と認識結果の書込みを行います。

- `data/events/`：通知に対応する動画・静止画像。
- `data/images/`：検出車両の切り抜きJPEG。
- `data/jobs/<処理ID>/input.*`：アップロードファイル。
- `data/jobs/<処理ID>/preview.jpg`：最新の処理済み映像。
- `data/jobs/<処理ID>/progress.json`：フレーム数・観測数・準備状態。
- `data/jobs/<処理ID>/worker.log`：モデル・入力エラー等の詳細。カメラ接続情報を含む場合があるため管理者のみで扱ってください。

ファイル・画像・ログの自動削除はありません。保存先の空き容量を管理してください。
映像の処理日時をUTCで記録し、Web画面では閲覧端末の現地時刻に表示します。撮影日時とは異なります。
同じ車両を連続フレームで検出すると複数レコードになります。表示件数は車両の通過台数ではありません。

`details_json` の `plate_candidates` にOCR原文・信頼度・候補枠・解析結果を保存します。

OCRでは候補枠の周囲に余白を加え、幅480pxを目安に最大4倍まで拡大し、上下段を分けて読みます。
通常画像で形式を解析できない場合や信頼度0.6未満の場合だけ、CLAHEによるコントラスト補正で再試行します。
`preprocessing` は選択された処理（`color` / `clahe`）です。信頼度を引き上げたり、推測で文字を置換したりはしません。
Webカメラは1920×1080を希望解像度として要求し、横幅最大1920px・JPEG品質92%で送信します。
実際の解像度はカメラとブラウザに依存します。送信は同時に1件までです。

実画像での改善率は未測定です。暗所・反射・斜め撮影・小さいナンバーや候補枠の検出漏れは残ります。
比較時は同じ元画像をファイル入力で読み込み、地域名・分類番号・かな・一連番号の全項目一致で確認してください。
誤読画像と正解番号を用意すると、切り出しの問題とOCRの問題を分けて調整できます。
解析結果は `region`（地名）、`category`（分類番号）、`kana`（ひらがな）、`serial`（一連指定番号）です。
形式が合う文字列でも確定番号ではありません。日本語は履歴に表示し、映像の枠ラベルは英語の車両区分です。

## 認識の範囲

車種は乗用車・軽自動車・二輪車・バス・トラックの5区分です。メーカー名・モデル名の識別は未実装です。
YOLOの車体検出では軽自動車を乗用車として検出し、ナンバープレートに強い色根拠がある場合だけ
`kei`（軽自動車）へ補正します。黄色地は自家用軽、黒地に黄色文字は事業用軽の候補です。
白地の図柄入り軽ナンバーは黄色枠を候補情報に記録しますが、図柄にも黄色が含まれ得るため
自動的には軽自動車へ変更せず、登録画面で確認します。

ご当地ナンバーの複数文字の地名（例: 富士山、伊勢志摩）は通常の地名と同じ形式で解析します。
図柄入りプレートでは、カラー・CLAHE・大津二値化・反転・適応二値化を順に試し、形式と信頼度が
最も良いOCR候補を採用します。候補には `plate_style`、`kei_candidate`、`kei_strength`、
`appearance_ratios` を保存します。地名を辞書で推測・置換する処理は行いません。
ナンバー領域抽出は輪郭と縦横比の簡易方式で、専用学習済みナンバー検出モデルは含みません。
夜間・反射・斜め・小さい文字、図柄と文字の重なりでは未検出や誤読が起きます。特殊形式のナンバーは未対応です。
入退場判定、車両追跡、通過台数の集計、ゲート機器制御は行いません。

設定完了まではワークフローをスキップします。

### 修正したナンバーによるOCR再学習

認識履歴から登録候補を取り込み、地名・分類番号・かな・一連番号を修正します。
「修正内容をOCR学習データにする」で、地名・分類番号・ひらがな・一連指定番号を個別に修正します。
4項目の正解欄には、選択したOCR候補の検出値を修正前データとして自動入力します。
正しく検出された項目はそのまま残し、誤認識した項目だけを訂正できます。候補を切り替えると初期値も切り替わります。
項目まで解析できなかった候補は自動入力できないため、登録欄と学習欄を手入力します。
各項目の画像範囲（左・上・右・下、全体に対する%）を調整し、文字が切れていないことを確認します。
保存済みデータも一覧の「正解・画像範囲を編集」から修正できます。
「修正した登録内容から正解を入力」で正解欄を埋め、画像中のハイフン・中点も含めて訂正してください。
確認チェックを付け「登録・更新と同時に学習データを保存する」を選ぶと、登録と学習データを一緒に保存します。
すでに登録済みのナンバーから画像を追加する場合は「学習データのみ保存」を使えます。
元画像のない履歴、候補枠のない画像は対象外です。枠に文字が収まらない画像は再撮影してください。
連続取り込みの一括登録は未確認データの学習を防ぐため対象外です。個別に画像と正解を確認してください。

「OCR再学習」で開始・状態確認・評価結果の確認・モデル適用ができます。
EasyOCRは学習処理との互換性を保つため1.7.2に固定しています。
再学習は日本語認識モデル `japanese_g2` の重みをCTC損失で更新します。文字の置換辞書ではありません。
ナンバー候補枠を検出する処理や車種モデルは学習対象外です。
CPUの2スレッド、バッチ4、学習率0.00001、最大10エポック、2時間の実行上限です。
画像数によって処理時間・メモリ使用量が変わり、認識と同時に動かすと遅くなることがあります。
初回はEasyOCRの日本語モデルをダウンロードします。オフライン環境では事前にモデルを配置してください。

ナンバーのハッシュで学習用・評価用を固定し、同じ番号を両方に入れません。
学習用5種類・評価用2種類以上が必要で、比率は概ね8:2です。不足数は開始時に表示します。
この下限は処理の実行条件であり、実用精度を保証する件数ではありません。
同一画像は重複除外し、正解が矛盾する場合は学習を中止します。
新しいデータは4項目の画像を個別に学習します。従来の上下段データはそのまま利用できます。
評価は項目画像（従来データは行画像）に対する文字誤り率（CER）と画像単位の完全一致率です。
学習開始時に選択されていたモデルに比べCERが改善し、一致率が悪化しなかったモデルだけ適用できます。
評価データでエポックを選択するため、未知の実画像による別途検証も必要です。
適用は手動です。認識処理を停止して再開すると反映され、実行中の処理には影響しません。
「標準OCRに戻す」で切り戻せます。元の配布モデルは書き換えません。

学習データは `gate.db` の `ocr_samples` に画像と正解、元OCR、認識結果ID、`ocr_sample_fields` に4項目の正解と範囲を保存します。
各学習時点の画像・ラベル・モデル・レポート・ログは `/data/ocr-learning/<学習ID>/` に保存します。
Dockerでは既存の `gate-data` ボリュームに永続化します。外部サービスへの画像送信は行いません。
データ削除は次回以降の学習対象からの除外です。過去のスナップショットやモデルには残ります。
スナップショットは自動削除しないため、定期的にディスク使用量を確認してください。

実画像の精度は未測定です。通常テストとは別に、EasyOCR/PyTorchを導入した環境で実モデルの学習・保存・再読込を確認できます。

```bash
GATE_TEST_OCR_TRAINING=1 python -m unittest discover -s tests -p test_ocr_training_model.py -v
```

### プレートの角度補正と登録車両の削除

OCR前にプレート候補の輪郭から四隅を推定し、射影変換で傾き・遠近歪みを補正します。
四角形を取得できない場合は、十分に矩形に近い輪郭だけ回転補正します。
枠を信頼できないときは補正せず元の候補画像を使います。上下反転や極端な角度の補正は保証しません。
候補の `quad_in_vehicle` と `rectification` に補正情報を記録し、学習画面にも同じ四隅で補正した画像を表示します。
これは枠の幾何補正であり、実車画像の認識精度向上は未測定です。

登録車両一覧の「削除」で確認後に登録を削除できます。編集中の車両なら入力欄もクリアします。
削除後は次回の照合から未登録車両として扱います。認識履歴・通知・学習データは削除しません。
削除APIにも認証とCSRF検証を適用します。
