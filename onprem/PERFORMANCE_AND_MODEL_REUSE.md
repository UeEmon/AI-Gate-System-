# 性能測定・自動最適化・モデル再利用

## Dockerへの反映

`onprem/deploy-local.sh`でgateとtrainerを更新します。通常の再構築ではデータ・モデルキャッシュを保持します。性能画面、OCR学習画面は通常のWeb管理画面に統合されています。AWSへの自動デプロイは停止したままです。

## 全フレーム計測

Web画面を閉じていても、処理した全フレームを `/data/jobs/<job_id>/performance.jsonl` に記録します。カメラから到着した全フレームではなく、間引き・最新フレーム選択後に処理した全フレームです。ジョブを削除するとその計測ファイルも削除されます。

記録する段階は入力待ち・デコード、前処理、車両検出、Liplaの検出・補正・OCR合計、判定、画像保存・DB・教師データ保存、通知キュー登録です。Liplaは内部段階のタイマーを公開していないため、検出・補正・OCRの個別時間は未測定（null）にし、合計を表示します。非同期のメーカー識別とメール配送完了時間は含めません。実運用の通知は従来の非同期配送です。

性能画面の集計は直近1000処理フレームの平均・中央値・95%遅延と、記録済み総フレーム数を表示します。FPSは処理フレームから算出します。入力FPSやフレーム間引きで推論能力が高くなったように表示しません。Webプロセスの子プロセスを含むCPU・RSSとホストメモリ使用率を取得します。NVIDIA情報を取得できる場合はGPU使用率・使用メモリを表示し、取得できない場合はnullです。Mac DockerのApple GPUをCUDA GPUとして扱いません。

## 実測による自動最適化

1. OCR信頼度98%以上の自動教師データを保存すると、同じ認識のフルフレーム画像もDBへ保存します。教師データを削除・更新して参照がなくなると画像も除外されます。自動教師データの既存上限500件を引き継ぎます。
2. 検証用に割り当てられた異なるナンバー2件以上で測定します。未使用テストや学習用データは設定選択に使いません。フルフレームが2件以上あればそれを優先します。古い車両切り出し画像だけの場合は参考測定となり、自動適用しません。
3. 基準入力サイズと640・960・1280を、常駐モデルと実際のworkerで測定します。各設定にウォームアップ1回、各画像に2回の測定を行います。保存・照合・通知は一時フォルダーのDBへ実行し、運用DB・教師データ・外部配送を変更しません。
4. 基準設定に対して、IoU 0.5での検出率と、運用OCR閾値を満たすナンバー完全一致率の両方が低下しない候補から、95%遅延の短い設定を選びます。基準設定の検出または完全一致率が0の場合は設定を変更しません。Liplaの高確度仮ラベルは独立した正解ではありません。少数標本のため、結果に標本数と評価範囲を記録します。
5. `profile=auto`かつフルフレーム評価の場合のみ設定を適用します。起動時は `GATE_AUTO_OPTIMIZE=1` で自動開始し、画像不足時は保留します。Webの「実映像で測定・自動最適化」からも開始できます。監視・学習・比較と測定の同時実行は共通ロックで防ぎます。

`onprem/.env` の `GATE_SOURCE_FPS` をカメラの入力FPS（既定30）、`GATE_TARGET_FPS`を目標処理FPS（既定10）に設定してください。処理間隔は目標FPSと95%遅延から算出します。間引きによって推論自体のFPSが上がることはありません。複数カメラや他のアプリによる負荷の変化は、実運用の性能画面で再確認してください。

## 学習済みモデルを再利用

OCR学習画面の「再利用パッケージをダウンロード」を使用します。現在の学習が完了し、同じモデルに対する未使用テスト2件以上の比較が完了していることが条件です。検出器、PaddleOCR推論グラフ・重み、再利用用Pythonクラス、依存関係、集計評価、SHA-256、ライセンス資料を含めます。教師画像、実ナンバー、登録・通知情報、APIキーは出力しません。運用モデルはLipla-jpのままです。

ZIPを展開して依存関係を導入し、`JapanesePlateRecognizer`を起動時に一度生成してBGR車両画像を渡してください。`validate_model_package.py`でZIP又は展開先のチェックサムを検証できます。詳細はパッケージのREADMEに記載します。

GitHub登録は `GATE_MODEL_REPO_TOKEN` にモデルリポジトリへのContents書き込み権限を持つトークンを設定し、`GATE_MODEL_EXPORT_LICENSE` に確認済みのモデル利用条件を設定してから、Webの「モデルをGitHubへ登録」を押します。既定の登録先は `UeEmon/AI-Gate-JP-Models` です。これらの値はパッケージに含めません。既存バージョンは上書きせず、同時更新時もforce pushしません。大きいファイルはGit LFS又はReleaseを利用してください。

## 回帰検証

GitHub ActionsのTestsでPython 3.11/3.12、Web UI、UMLサーバーを検証します。疑似推論を使う回帰テストは実モデルの精度測定ではありません。実際のDockerイメージビルド、Mac上の学習、実データの測定結果は運用環境で確認します。
